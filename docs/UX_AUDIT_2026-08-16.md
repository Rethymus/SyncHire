# SyncHire Lite 用户体验走查报告

> 走查日期：2026-08-16 · 走查方式：以首次使用的求职者身份，在 Windows + Chrome（1440×900 与 390×844）完成「启动 → 仪表盘 → 建职位描述 → 申请跟踪 → 岗位信息流 → 数据源 → 招聘雷达 → 角色卡 → 数据管理 → 设置」全流程，并对每个页面截图、记录控制台错误与网络失败。
>
> 本报告先给结论，再按学科分类列出问题（每条标注严重度 P0/P1/P2），最后附修复方案与所用开源轮子。

## 一、总体结论

产品定位清晰（本地优先、隐私可控、围绕岗位组织求职），文案质量高，页面骨架完整，控制台零报错。但在**启动可靠性、导航信息架构、移动端可用性、关键流程连贯性**四个方面存在明显短板：一个新用户在 Windows 上按 README 启动会直接看到全站 Build Error（P0）；在手机上几乎无法导航（P0）；在申请页点「新建申请」会被踢回仪表盘而不是就地创建（P1）。这些都是「最后一公里」问题——功能都在，但没被顺手地送到用户手上。

## 二、软件工程视角

### SE-1（P0）依赖安装不可复现：workspace 提升导致全站 Build Error
- 现象：按 README 执行 `npm install` 后启动前端，所有页面渲染 Next.js Build Error。根因是 npm workspace（npm/cli#4828）把 `@tailwindcss/oxide` 提升到根 `node_modules`，但平台专属可选包 `@tailwindcss/oxide-win32-x64-msvc` 未被安装。
- 危害：Windows 新用户 100% 被阻塞，且报错文案（英文堆栈）指向「删除 lockfile 重装」这种破坏性建议。
- 修复：将平台二进制加入根 `package.json` 的 `optionalDependencies`（npm 会按 os/cpu 字段自动跳过不匹配平台），使安装可复现。

### SE-2（P1）路由迁移残留：`/zh/*` 全部 404
- 现象：README 大量宣传 `zh-linux-*.png` 截图与中文路由，但当前 App Router 已改为无 locale 前缀路由（`/dashboard`），`src/app/[locale]/` 只剩落地页残壳；`/zh/dashboard` 等 404。
- 同时导航里 4 个菜单项文案用 `locale === "zh-CN" ? "岗位信息流" : "Job Feed"` 内联三元式硬编码，绕开了 `lite-i18n` 文案体系，i18n 架构被架空。

### SE-3（P1）API 客户端七代同堂
- `lib/` 下并存 `api-client.ts / -lite / -unified / -v2 / -enhanced / -consolidated …`，命名即考古地层。新贡献者无从判断该用哪个；死代码与重复错误处理逻辑并存。建议收敛到 unified 并用 codemod 删除旧层。

### SE-4（P2）巨型组件
- `settings/page.tsx` 1771 行、`profile` 页把角色卡与填表助手两大领域塞进一个文件。建议按 Tab 域拆分组件（项目已有 `ui/tabs.tsx`）。

### SE-5（P2）表单校验静默失败
- `jd-input` 的 `handleSubmit` 对空必填字段直接 `return`，无任何应用级反馈；用户只能看到浏览器原生英文气泡提示，与全中文界面割裂。

## 三、人体工程学 / 人因工程视角

### ERG-1（P0）移动端导航缺失
- 390px 视口下导航栏只剩 Logo 和一个图标。该图标是「设置」形状，链接却指向 `/data`（数据管理）——语义误导 + 功能缺失双重问题。用户在手机上无法到达简历、职位描述、申请等任何核心页面。
- 违反 Nielsen 可见性原则（系统状态可见 / 入口可发现）与 WCAG 2.4.5（多种途径可达）。

### ERG-2（P1）一级导航 10 项平铺，违背 Fitts/Hick 定律
- 桌面端把 10 个菜单项 + 语言切换水平挤进 64px 高的顶栏，每项点击区约 `px-3 py-2`（≈ 32px 高），低于 44×44px 的最低触达标准；项目数逼近工作记忆上限（7±2），选择时间随项数线性增长。
- 且无分组：核心求职循环（简历→职位→申请）与低频工具（搜索、数据管理）混排，没有视觉层级。

### ERG-3（P1）申请页 CTA 跳转而非就地操作
- 「新建申请」按钮实际是 `<Link href="/dashboard">`。用户的心智模型是「在这里创建」，系统却要求「先去另一页」。操作距离被人为拉长，且仪表盘入口同样叫「新建申请」，造成回环。
- 组件 `ApplicationCreateDialog` 已存在，只是没有在申请页复用——纯粹的接线问题。

### ERG-4（P2）空状态信息过载
- 申请数为 0 时仍渲染 8 张统计卡（全为 0）+ 完整排序/筛选面板。空态的首要任务是引导第一步动作，而不是展示无意义的零值仪表。认知负担与视觉噪音双高。

### ERG-5（P2）按钮次序与破坏性操作
- JD 表单「继续下一步」（主）在左、「取消」在右，与通用惯例（主操作居右/居尾）相反；「取消」点击即 `router.push` 离开页面，已填内容无任何保护。

## 四、设计学视角

### DES-1（P1）设计令牌体系与页面实现脱节
- `globals.css` 有完整的 shadcn 式语义令牌（`--background/--card/--muted`，含 `.dark` 暗色值），但 Lite 各页面大量硬编码 `bg-white / text-gray-900 / bg-gray-50`，令牌被架空：换主题、做暗色、统一品牌色都要改几十处。
- 圆角混用 `rounded-lg / rounded-2xl`、阴影 `shadow-sm` 与无阴影并存，卡片密度不统一。

### DES-2（P1）组件库已有却不用
- `components/ui/` 已有 25 个 shadcn 风格组件（含 `empty-state.tsx`、`dialog.tsx`、`dropdown-menu.tsx`），Radix 全家桶也已安装；但页面里仍手写按钮 class、手写空态、手写下拉。既造成视觉不一致，也让 a11y（焦点管理、aria 属性）依赖每次手写的运气。

### DES-3（P2）暗色模式名存实亡
- 令牌定义了 `.dark`，无切换入口，页面硬编码浅色。求职者晚间高频使用，暗色是真实需求（后续用 next-themes 轮子补齐即可，本次先立骨架不动全站）。

### DES-4（P2）空状态视觉单薄
- 仅灰色图标 + 文案，缺少与品牌一致的插画/图形语言；各页空态样式也不统一（有的有按钮、有的没有）。

## 五、修复方案（本次实施）

| # | 问题 | 方案 | 复用的轮子 |
|---|------|------|-----------|
| F1 | SE-1 装机即崩 | 根 `package.json` 增加平台二进制 `optionalDependencies` | npm 原生 os/cpu 过滤 |
| F2 | ERG-1/ERG-2 导航 | 重构 `navigation-lite.tsx`：桌面端 5 个核心项 + 「更多」下拉收纳低频项；移动端汉堡菜单侧滑抽屉；修正设置图标误链；补设置入口；文案全部回归 i18n | **Radix DropdownMenu / Radix Dialog**（已安装）；抽屉样式参考 **shadcn/ui Sheet**（MIT，本质即 Radix Dialog） |
| F3 | ERG-3 申请页 CTA | 引入 `ApplicationCreateDialog` 就地打开，空态按钮同样打开对话框 | 项目内已有组件 |
| F4 | ERG-4 空态过载 | 申请列表为空时隐藏统计与筛选面板，聚焦单一引导 CTA | — |
